# 常见问题

先看最早出现的错误，不要连续重复点击编译。反馈时附上版本、操作步骤和错误文字，删除姓名、学号及未公开论文内容。

| 现象 | 先做什么 |
| --- | --- |
| Python / Pandoc 未找到 | 确认下载的是 Releases 完整包，并完整解压 `runtime`；Source code 不含环境 |
| 解压报 `0x80010135` 路径太长 | 换到 `D:\XIT` 等较短位置重新完整解压，不要跳过报错文件 |
| 双击后无网页 | 保留启动窗口，查看其中地址和错误；将本机地址复制到浏览器 |
| 端口被占用 | 关闭同一项目的旧助手再启动；不要同时开启多个实例 |
| 页面提示保存失败 | 先复制当前文字到安全位置，再处理磁盘权限、服务退出等问题 |
| PDF 没有变化 | 确认保存成功、编译完成；检查是否仍显示上次成功结果 |
| 提示图片不存在 | 按提示找到文件和行号，重新上传图片或修正路径 |
| 参考文献显示问号 | 核对正文代号与库中代号；查看 Biber 错误，重新完整编译 |
| 原字体缺失 | 可先用随包字体预览；正式版本按要求合法安装原字体后重新编译 |
| `mktexfmt xelatex.fmt` 后失败 | 查看日志后续关键错误；确认完整解压、目录可写，优先使用短路径 |
| 双击 PDF 无法定位 | 先成功编译一次；尝试正文段落，封面、目录等自动生成内容不一定有映射 |

## 离线使用需要满足什么条件

完整包已解压、运行文件未被移除、论文使用的图片、字体和宏包都已在本机时，日常编辑与编译可以离线运行。界面通过本机地址打开，不代表正在使用互联网服务。新增宏包、下载更新和查询文献仍需要网络。

## 意外关闭后如何继续

回到原文件夹，用原浏览器重新打开助手。已显示“内容已同步”的内容应已写入项目文件。若出现未同步草稿提示，先预览并核对内容，再恢复。清理浏览器数据、移动项目、改变访问地址可能影响本地草稿读取。

如果没有草稿提示，查看“历史版本 / 恢复”或已有整篇备份。不要一开始就覆盖整个文件夹或重新解压到旧项目上，以免覆盖自己的论文。

## Windows 与字体边界

完整包面向 Windows 10/11 x64。ARM、不同系统版本和受限机房未全部验证。安全软件移除文件时先查看隔离记录与文件来源，不建议关闭安全防护。受管理电脑的权限问题请联系管理员。

开源替代字体不是宋体、黑体、Times New Roman 的同一份字体。能成功生成 PDF，不等于已满足学院的格式要求。请按当年要求人工复核。

更详细的环境说明见[Windows 兼容与环境修复](../Windows兼容与环境修复.md)。
